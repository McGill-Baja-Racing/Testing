# Detailed test report

Use for complex tests or when a short issue summary cannot explain critical evidence. Keep the original test issue as the results/decision index; link this report, not a duplicate report issue.

Required: test ID/parent issue, revision/author/date and reviewers.

1. Objective, decision, requirement references, sufficient evidence and applicable criteria/basis.
2. Actual method: configuration/conditions, personnel, equipment/device/install/calibration references, run IDs, procedure and deviations.
3. Evidence index: original recordings/logs, processed outputs, code commit/settings and reproducibility steps. Preserve rejected runs and rejection reasons.
4. Results: metrics, uncertainty, data quality, limitations and applicability.
5. Attempt validity separately from design outcome; engineering interpretation and unresolved questions.
6. Follow-ups with owner/timing; DVP&R changes; evidence reuse/reverification justification.
7. Subsystem Lead interpretation sign-off and Testing Manager closure-record check links.

Optional appendices: error budget, experiment design, calibration plots and extended analysis. Reference existing records rather than repeat them. [Short summary](results-summary.md).
