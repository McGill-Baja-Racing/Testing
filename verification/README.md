# Verification records

DVP&R means **Design Verification Plan and Report**: requirements, methods, criteria and evidence for engineering decisions. [Standard and status meanings](../docs/standards/verification-strategy.md).

**No production requirements or verification evidence have been supplied in this revision.** Subsystem Leads create focused records from the [blank template](../templates/dvp-r.md); do not adopt fabricated limits from examples. Managers maintain the vehicle overview and review gaps at major milestones.

| Record | Use |
| --- | --- |
| [Vehicle validation overview](vehicle.md) | Operational register awaiting owner-defined entries |
| [Drivetrain EXAMPLE](subsystems/drivetrain.md) | Complete fictional rows showing criteria, basis and linked evidence gaps |
| [Suspension EXAMPLE](subsystems/suspension.md) | Fictional inspection/analysis planning |

Keep historical example IDs stable. Real requirements use owner-allocated subsystem IDs independent of test issues. Closing a test never automatically verifies a row; evidence must apply to the configuration/conditions and satisfy the criteria.
