# Test Lead quick start

**Direct the individual test and preserve a usable record of what happened.** The Testing Manager coordinates the day; the Subsystem Lead owns the objective.

## Before the day

Use the [common plan](../../templates/test-plan.md), linking the parent request instead of retyping it. Confirm configuration, people, equipment, procedure, runs/repeats, conditions/controls, hazards, stop rules, data checks and recording locations. Add complex/safety/experiment sections only when justified. Agree the Analysis Owner and due date. Check [readiness](../../templates/readiness-checklist.md) with the technical owners before the Testing Manager confirms the schedule.

## At the site

1. Confirm the actual configuration and required technical/safety clearance. Obtain the Subsystem Lead and Testing Manager's joint go/no-go; Scheduled is not permission to operate.
2. Assign each run a unique ID and complete the [CSV log](../../templates/run-log.csv): time, configuration, conditions, observations, deviations, raw-data/calibration references, operator and data quality.
3. Anyone can stop unsafe work. Secure the operation and record why. Resume only after proper clearance and renewed joint go/no-go. Refer configuration changes to the Testing Manager for reassessment with relevant owners.
4. Check data after each run when feasible, at minimum before leaving where practicable. Check units, timestamps, scaling, saturation/dropout and file readability; record omitted checks and reasons.

## Hand off

Preserve raw originals and failed/aborted runs; link logs, configuration and calibration versions. Confirm access and the Analysis Owner's due date. Record deviations and unresolved questions in the parent issue. New investigations use new linked requests, not an unapproved extension of scope.
