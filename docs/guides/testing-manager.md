# Testing Manager quick start

**Coordinate the process and check completeness; Subsystem Leads own objectives and interpretation.**

1. At intake, confirm the requesting Subsystem Lead and objective completeness. Use the issue-derived [test ID](../data-storage.md#test-and-run-ids). Ask Electronics/relevant specialists for quick screening before Managers' review. Return precise questions rather than guessing the measurement need.
2. Index the [decision records](../../templates/approval-record.md) in the parent issue. Track value approval, bounded investigation if needed, resource commitments before Managers' preparation authorization, readiness and final go/no-go separately. Never treat assignment, a label or Project status as authorization.
3. Coordinate the [common plan](../../templates/test-plan.md). Medium/high work uses linked preparation issues; low effort stays a checklist. Name the Test Lead, Instrumentation Owner and Analysis Owner, with an agreed analysis due date. Resource managers set capacity and work-in-progress limits.
4. Check installed-configuration [readiness evidence](../../templates/readiness-checklist.md) with technical owners. Only prepared tests enter a confirmed day; keep speculative dates in planning. Managers resolve time conflicts. Plan significant tests normally three to four weeks ahead, while allowing smaller/urgent requests through the same proportionate gates.
5. Follow [test-day operations](testing-day.md). After changes, determine reassessment scope with relevant technical/safety owners and repeat affected checks. Substantial scope changes return to screening and revised authorization. Jointly decide execution go/no-go with the Subsystem Lead, subject to mandatory clearance.
6. Track [analysis and closure](closure.md): remind overdue owners, then escalate unresolved work. Check records before closing the attempt; the Subsystem Lead approves conclusions. Invalid/inconclusive attempts need linked follow-ups for unresolved objectives; do not mark requirements verified.

Alternative methods must answer the original question; unexpected observations needing a new investigation become new linked requests. You and affected leads can reorder approved work, not authorize new formal tests.
